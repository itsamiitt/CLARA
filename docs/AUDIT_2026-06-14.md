# CLARA — Audit & Hardening, 2026-06-14

Authoritative current-state record. Supersedes `CLARA_V4_BUG_REPORT.md`,
`CLARA_BUG_FIXES.md`, and `buggy.md` (all historical).

## TL;DR

A fresh, code-verified audit found the **core code is sound**. Every bug in the
earlier reports (#1–#13) is **fixed or mitigated**. The audit's remaining
findings were low-severity hardening + test-coverage gaps, which this change
addresses. No critical data-correctness bug exists in the current code.

## Verified fixed / not-bugs (do not "re-fix")

- **Native LanceDB ANN search** — `retrieval/engine.py` uses
  `table.search().metric("cosine").where(prefilter=True).limit()`, not an
  in-memory scan (old #9).
- **Decay → LanceDB sync** — decay/pruning mutate ORM objects, firing the
  `before_flush`/`after_commit` listeners; status changes propagate to LanceDB
  via the metadata-only update path (old #10). Now covered by a regression test.
- **after_commit instance routing** — reads `session.info["_lance_engine"]`
  with a default fallback (old #11).
- **Embedding cache** — reset via `@reconstructor` + expire/refresh listeners
  (old #12).
- **World-model race** — `begin_nested()` + `IntegrityError` retry + a real
  partial unique index (SQLite *does* enforce `CREATE UNIQUE INDEX … WHERE`)
  (old #3).
- **BackgroundWriter** wired via `remember(wait=False)` (#5); **API auth +
  tenant scope** present (#7); **OpenClaw** scoped by `user_id` (#8).
- Audit-agent "new" claims that **did not hold up**: belief reinforce already
  respects domain (`_same_belief`); negation-vs-negation/different-object is not
  a real contradiction; belief `prior_weight=1.0` = observation count.

## Changes applied in this pass

### P0 — safe nits + regression tests + doc truth
- `memory/skill.py`: deprecation threshold now inclusive (`<=`).
- `retrieval/embeddings.py`: `normalize_embedding_dimensions` warns (once per
  source size) when truncating oversize vectors instead of silently dropping the tail.
- `memory/event.py`: warns on an unrecognized `event_status` before defaulting.
- `extraction/extractor.py`: warns on an unexpected Ollama response shape.
- `pyproject.toml`: pin `lancedb>=0.20,<1.0`.
- `api/app.py`: one-time startup warning when `auth_required=False`.
- Tests: `test_decay_search_integration.py` (decay/prune → excluded from
  `recall()`), `test_text.py` (sanitiser), plus classify/embeddings/admin cases.
  (API 401/403 auth edges were already covered.)

### P1 — design-gap improvements
- **Prompt-injection hardening**: new `core/text.py:sanitize_memory_text`, applied
  in both `agent.py` and `reasoning/context.py` `_format_*` (strips control chars,
  defangs `===`/`[SECTION]` markers) so stored memory can't inject prompt structure.
- **Skill matching**: `skill.match()` now falls back to `LexicalRetriever`
  (keyword search) when no embedding engine is bound (e.g. the zero-backend path).
- **`classify_memory_type`**: relations are normalised (`spaces`/`-` → `_`) and
  keyword sets broadened; precedence (event > skill > world_model > belief) documented.
- **Observability**: `ReasoningResponse.facts_considered` + surfaced in
  `agent.interact()`.

### P2 — concurrency, API surface, deployment parity
- `tests/test_retrieval_stress.py` (`@pytest.mark.stress`): concurrent recalls
  interleaved with writes.
- `api/app.py`: opt-in CORS via `CLARA_CORS_ORIGINS`.
- `api/routes_admin.py`: admin data routes require auth when `auth_required`
  (`/admin/health` stays open for liveness).
- `db/models.py`: added `postgresql_where` to the world-model unique index (see
  Postgres note below).
- LLM resilience: OpenAI/Anthropic clients now use `timeout` + `max_retries`
  (`extraction/extractor.py`, `reasoning/engine.py`).

## Known limitations / follow-ups
- **PostgreSQL**: CLARA is SQLite-first. The world-model unique index uses
  `json_extract(...)`, which is SQLite syntax; true Postgres support additionally
  needs a dialect-aware index expression (`content->>'…'`). The `postgresql_where`
  predicate is in place for when that is done.
- **Dropped from plan, intentionally**: emitting `ActionTaken.skipped` — the
  pipeline has no honest "skip" path (every extracted fact yields created /
  reinforced / superseded / retained_both), so a fake skip was not introduced.
  `facts_considered` provides the intended observability instead.
